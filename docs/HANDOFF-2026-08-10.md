## One test is red on purpose

`the_no_qualified_reader_ledger_is_exact` (15 of 16 guard tests pass). It claims
`risk.trailing_*` and `challenge_mode` now have production readers. They do not.
The reads it found are `p.trailing_be_trigger_r` where `p` is an
`ExitPolicyConfig` bound by `Some(p)` in a match arm — a different struct with
identical field names. The binding collector only resolves `ident: Type`
annotations, so the receiver is unresolved and credited by field name. The guard
has a passing test for this class but it does not cover match-arm bindings.
Deleting those ledger entries would record five orphaned knobs as working.
**Fix the guard, not the ledger:** teach the collector that `Some(x)` matched on
`let x: Option<T>` binds `x` to `T`.

It also correctly wants `SystemConfig::n_jobs`, `num_gpus` and
`ModelsConfig::inference_batch_size` reclassified WrittenNeverRead → Unwired;
their only writer went out with the deleted `NEOETHOS_BOT_*` env layer.
